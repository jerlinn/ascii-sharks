# ascii-sharks 原理

鲨鱼和鱼群没有用任何贴图、精灵图或预画的 ASCII 字符画，每一帧都由三层计算生成。**模拟层**（`World`）只关心点和速度：鲨鱼是一条 20 节点的脊椎，鱼是一个质点。**形状层**（`sampleShark`）把屏幕上的任意一点换算到鲨鱼的身体坐标里，判断它落在身体、鳍、眼睛还是外面。**着色层**（`drawSharks`）把每个格子的明暗翻译成一块灰色方块加一个字符。

三层之间是单向数据流，改造时先判断要改的东西属于哪一层，就能把影响范围锁定在一个文件里。

三层之上是**场景**（`Scene`，scene.ts）：出场的大型生物、小鱼物种表、背景色、网格色、尾迹色、鱼的颜色、皮肤强调色和光源方向。模拟和渲染代码所有场景共用，场景只提供数据。场景只有一个来源，就是 `World.scene`。渲染器每帧比较一次场景的引用，发现变了就重建自己的配色缓存，所以切换场景只需要调用 `OceanEngine.setScene()`，不用另外通知渲染器。现在的海洋就是 `OCEAN`。

```
OceanEngine (engine.ts)        固定步长 1/60 s，一帧最多追 4 步
  └─ World.step(dt)            world.ts      模拟：鱼群 boids + 鲨鱼转向 + 脊椎跟随
  └─ AsciiRenderer.render()    renderer.ts
       ├─ rasterizeSharks      脊椎 → 身体波动 → 逐格超采样 → flag / shade / key
       ├─ depositWake/diffuse  尾迹能量场扩散
       ├─ drawDots             尾迹亮点（青色）
       ├─ drawHeat             捕食处的红色余烬
       ├─ drawFish             每条鱼一个 "-"
       └─ drawSharks           方块底色 + 字符 + 偶发强调色
```

## 1. 单位与坐标系

整个系统用到四套坐标，混淆它们是改造时最常见的 bug 来源。

| 坐标 | 含义 | 出现位置 |
|---|---|---|
| 像素 `(x, y)` | 画布 CSS 像素，模拟与采样都在这里进行 | `World`、`sampleShark` 的入参 |
| 格子 `(col, row)` | 字符网格，`cw = clamp(width/124, 8, 13)`，`ch = cw × 1.45` | 渲染层所有 `Uint8Array/Float32Array` 场 |
| 体长分数 | 形状参数一律是体长 `L` 的分数，所以同一套参数适用任何尺寸 | `SHAPES` |
| 身体坐标 `(s, v)` | `s` 是沿脊椎的弧长比例（0 吻端 → 1 尾尖），`v` 是到脊椎的带符号距离（像素） | `sampleShark` 的输出 `hitS / hitV` |

格子不是正方形（宽高比 1 : 1.45），但采样发生在像素空间，所以鲨鱼形状不会被拉扁。只有在格子空间里做距离计算时才需要手动校正，例如 `stamp()` 里的 `(r - r0) * 1.4`。

## 2. 姿态

### 2.1 模拟脊椎：follow-the-leader

`Shark.nodes` 存 20 个节点，吻端在前。每步只有吻端按 `heading × speed` 前进，其余节点依次被前一个节点「拖着走」，间距固定为 `L / 19`。

决定姿态合法性的是 `stepSharks` 末尾的关节刚度限制 `maxBend = 0.16` 弧度：每个关节相对前一段的偏转不超过这个值。19 个关节累计最多约 3 弧度，身体最多弯成 C 形，永远不会对折。这是姿态不崩的唯一保证，调大它会出现鲨鱼折叠成 U 形穿过自己的画面。

转弯能力由 `agility = min(hunting ? 1.7 + closing : 0.8, speed / (L × 0.22))` 决定：速度越快、体型越长，转弯半径越大，所以鲨鱼不能原地掉头。`sh.turn` 是平滑后的角速度，模拟层不用它，它只是交给渲染层做侧倾的信号。

### 2.2 渲染脊椎：行波

`rasterizeSharks` 不直接画模拟脊椎，而是先在其上叠加一道沿身体向后传播的横向正弦波：

```
amp(s) = L × 0.05 × (0.1 + 0.9 × s^1.8) × swim
off(s) = amp(s) × sin(phase − 5.2 s)
```

`s^1.8` 让头部几乎不动、尾部摆幅最大，这是鲨鱼（鲹科式游泳）的特征。`−5.2 s` 让波峰从头传到尾，`phase` 的增速随 `speed` 提高，游得越快摆得越勤。`swim` 把振幅也绑定到速度。

这个波只存在于渲染层，不回写模拟，所以它不影响捕食判定和碰撞。想改游泳姿态（鳗鲡式全身波动、金枪鱼式只摆尾），改的是 `amp` 的指数和 `5.2` 这个波数。

### 2.3 侧倾

转弯时用 `sh.turn` 算出 `bank ∈ [−0.35, 0.35]`，同时作为横滚角（弧度）使用。鲨鱼向转弯内侧横滚，带来三个可见变化：

1. **胸鳍**：胸鳍静止时下垂 `PECTORAL_DROOP = 0.35` 弧度，俯视长度是真实长度乘 `cos(倾角)`。横滚后内侧倾角变为 `droop + bank`，外侧变为 `droop − bank`。投影只会缩短不会拉长，所以外侧鳍放平时最多显示真实长度（相对静止约 +6.5%），视觉变化主要来自内侧鳍缩短（约 −19%）。`pectoral[3]` 定义为静止下垂状态下的俯视长度，真实长度由它反推。鳍的拍动也作用在倾角上，而不是直接缩放长度，否则同样会突破真实长度这个上限。
2. **背脊**：背中线横移到 `rollX = −sin(bank)`，背鳍高光带随之滑向内侧。
3. **腹部**：外侧边缘露出浅色腹部（反荫蔽色）。

符号约定：`bank > 0` 时转弯内侧是 `v < 0` 那一侧。原代码在这里写反了（内侧鳍被拉长了），现已修正。

光照公式不随横滚改变，这是有意为之，见 §3.1。

### 2.4 形状：身体坐标里的轮廓函数

`sampleShark(px, py)` 遍历 19 段脊椎，找到离该点最近的那段，得到 `s`、`a = |v|` 以及那一点的侧向法线 `(bestNx, bestNy)`。随后的所有判断都在 `(s, v)` 里完成，按优先级依次是：

1. **锤头的头翼**：`shape.head` 存在时，在吻端附近划出一块横向宽翼，翼尖（`r > 0.84`）就是眼睛。
2. **躯干**：`a ≤ halfWidth(s) × L`。躯干内部再按 `s` 区间细分为第一背鳍（高光脊）、第二背鳍、眼、五道鳃裂、吻尖、斑纹。
3. **胸鳍**：在 `(u, a)` 平面上的三角形，镰刀形（falcate）的会再挖掉一个三角做出凹形后缘。
4. **腹鳍与叉形尾鳍**：同样是三角形。

关键在于轮廓定义在身体坐标里而不是屏幕坐标里。脊椎怎么弯，`(s, v)` 就怎么弯，同一组参数自动适配任何姿态。但这条只适用于躯干。鳍是刚性的附肢，在根部跟着身体转，本身不随躯干弯曲。身体坐标在弯曲处会呈扇形张开：离脊椎越远，同样一段弧长在屏幕上越长，外侧拉长约 `1 + 离脊椎距离 × 曲率` 倍。长鳍在急转弯外侧会被拉长将近一倍，内侧则被压扁。所以胸鳍和腹鳍改在鳍根处的框架里判定：`spineFrame` 每帧在鳍根处取脊椎上的点和切线，样本点投到这个直框架里，再代入原来的鳍形公式。侧倾时的 cos 投影缩短照旧适用。

但完全刚性又走到另一个极端：鳍以固定角度钉在鳍根上，像插了两根木棍。所以 `poseFin` 会先把样本点绕鳍根转一个角度，再判定鳍形（`SHAPES[*].finMotion`）。这里是旋转，不是拉伸，鳍的长度始终不变。转角由三部分组成：
- **弧度**（`arch`）：越靠近鳍尖，向后掠得越多，静止时鳍就是一道弧。鳍根相应往前回收一半，所以弧度只改变弯曲，不改变鳍的平均朝向。
- **摆动**（`flap`）：鳍根只在静止姿态之前摆动，不往后掠。因为鳍是从体内长出来的，往后掠会让更多部分埋进身体轮廓，露出的部分就显得变短了；座头鲸的胸鳍掠到 27° 时只剩一小截。
- **鳍尖滞后**（`lag`）：鳍尖比鳍根慢一拍，摆动时鳍像一支有弹性的桨，而不是整根杆子在转。

座头鲸缓慢地摆动它的长胸鳍，锦鲤一直在划，鲨鱼的胸鳍很硬，几乎不摆动。鲨鱼长三角鳍露在体外的只有鳍尖那一截，摆动几度就会有一大段缩进身体。还试过一个方案：让鳍按身体在鳍根处的曲率跟着弯。结果转弯时外侧的鳍被转向身体、被身体盖住，内侧的鳍被转开成一根竖棍，已经撤掉。鳍根之后的躯干怎么弯，和鳍无关。新增物种只需要往 `SHAPES` 里加一项：一条 `halfWidth(s)` 曲线加上几组鳍的位置参数。

`halfWidth` 的典型结构是四段：吻部用 `sin` 的幂次做圆头（幂次越小头越钝，tiger 0.45、classic 0.95、mako 1.5），胸部用 `smoothstep` 稍微鼓起，躯干用 `(1 − t)^p` 收窄到尾柄，尾部用一个 `sin` 小鼓包做尾鳍根部。

## 3. 立体感

### 3.1 明暗：圆柱上的 Lambert 漫反射

立体感的核心是 `sampleShark` 里的两行：

```ts
const facing = (bestNx * -0.6 + bestNy * -0.8) * across;
let shade = 0.58 - across * across * 0.42 + facing * 0.26;
```

把俯视下的鲨鱼横截面看作圆柱，`across = a / halfWidth ∈ [0, 1]` 就是该点在截面上的归一化横向位置。圆柱表面法线可以拆成两部分：

| 法线分量 | 精确值 | 代码中的近似 | 视觉效果 |
|---|---|---|---|
| 朝上（z） | `√(1 − across²)` | `1 − across²/2`，即 `−0.42 · across²` | 背脊亮，两侧暗 |
| 水平（xy） | `across × 侧向法线` | `facing` | 朝光的一侧亮 |

光源方向是屏幕空间的左上方 `(−0.6, −0.8)`，再加一个隐含的竖直分量。所以 `shade` 就是法线点乘光照方向，只是把平方根换成了二次近似。侧向法线来自脊椎的实时切线，鲨鱼掉头后，亮面会自动换到另一侧，光源始终固定在屏幕上。

调参含义：`0.58` 是背脊基础亮度，`0.42` 控制边缘衰减（越大越「圆」），`0.26` 控制左右明暗差（越大光越侧）。

一个反直觉的推论：**圆柱绕自身轴线转动，从正上方看明暗完全不变**，因为屏幕上每个横向位置看到的法线都和原来一样。所以表现横滚不能去改光照，只能移动表面的标记。`fromBack = |across × sign − rollX|` 是该点到背中线的距离，背鳍、第二背鳍都按它判断，因此会随横滚移位。`fromBack > 1` 的区域在不横滚时根本看不到，对应外侧翻上来的腹部，用 `smoothstep(1, 1.25, fromBack)` 把反照率最多提高 90%。直行时 `rollX = 0`、`fromBack ≤ 1`，画面和引入横滚之前逐像素一致。

### 3.2 亮度的双重编码

`drawSharks` 让每个躯干格子输出两层：

1. 一块灰色方块，亮度 `level = 46 + shade × 160`，再乘物种色调 `tint`。
2. 一个深色字符，从 `SKIN_RAMP = ":;t%SX8#@"` 中按 `(1 − shade)` 选取，越暗的地方笔画越密。

方块越暗的地方，字符的墨也越多，两个信号方向一致，明暗对比被放大。如果把这个对应关系反过来（亮处用密字符），纹理会和光照打架，整只鲨鱼看起来就是平的。新增字符集时要保持「从稀到密」的顺序。

### 3.3 其余深度线索

| 线索 | 实现 | 位置 |
|---|---|---|
| 背鳍高光 | `FLAG_RIDGE`，`shade = 1`，字符 `@8%` | `sampleShark` |
| 景深 | `depth` 同时控制体长、亮度（`dim = 0.7 + 0.3 × depth`）和绘制顺序 | `seed`、`drawSharks` |
| 水体雾化 | 越深越向 `Scene.fog`（水色）靠拢，方块按比例混色，字符用 `globalAlpha` 降低对比度；`fog = min((1 − depth) × FOG_RATE, FOG_MAX)` | `drawSharks` |
| 遮挡 | `seed` 按体长升序排序，深的先画，近的后画盖住深的 | `seed`、`rasterizeSharks` |
| 交叠暗边 | 近处生物的轮廓边缘落在更深生物的实心格上时，不覆盖，只给那一格记上遮挡 | `rasterizeSharks` |
| 投影 | 实心格沿光源反方向偏移 `SHADOW_DROP × L`，落在更深的生物身上时把它压暗到 `SHADOW` | `rasterizeSharks`、`drawSharks` |
| 鱼的远近 | `f.depth > 0.78` 的鱼先占格子，近处的鱼亮 | `markFish` |

这四条线索是一起起作用的。早先只有亮度乘 0.7–1.0，深处生物的颜色和对比度都和近处一样；近处生物的半透明轮廓格还会整格替换掉深处生物的实心格，在它身上打出一圈「洞」。两条生物一交叠，笔画就搅成一团。现在 `sharkShadow` 记的是「给这一格投下阴影的最近生物的深度」：投影和交叠暗边都写进这里，`drawSharks` 只在这一格自己的生物更深时才压暗，所以生物不会被自己的影子压暗。投影方向跟随 `Scene.light`。

投影对海床背景点仍然没有效果：环境点从不绘制（`dotKind` 全为 0，`DOT_RGB` 前四种颜色因此闲置），尾迹点也不读阴影。

### 3.4 边缘与纹理稳定性

每个候选格子取中心点加 4 个子采样点（`SUBSAMPLES`），共 5 个样本。中心命中且覆盖率 ≥ 0.6 的格子算实心，否则算边缘，用轻字符 `.',` 或 `:;` 表示，这就是字符画上的抗锯齿。

字符的选择由 `hash3(round(s × 52), round(v / (cw × 0.9)), sh.id)` 决定，即**按身体坐标取哈希，而不是按屏幕坐标**。所以纹理贴在皮肤上随身体移动，不会在身体表面滑动。颜色闪烁（强调色、白点）也用这个 key 错开时钟，所以整体是缓慢地闪，而不是全屏同步跳变。

## 4. 鱼群与生态

鱼群是 Reynolds boids 的三项力（分离、对齐、聚合），加上 Couzin 式的分区和背后约 127° 的盲区。物种差异完全由 `species.ts` 里的权重决定：对齐强得到带状鱼群，对齐弱得到蜂群，`mill > 0` 的切向力让沙丁鱼群旋转成饵球。

分离用的是椭圆个人空间，宽高取自 `spacing × (cw, ch)`，单位是格子。这个设计保证每条鱼大致占据独立的格子，渲染时一格一个 `-`，不会因为重叠丢鱼。改格子尺寸时，鱼群密度会自动跟随。

恐慌通过 `alarm` 传播：直接看到威胁时置高，邻居之间以 0.86 的系数逐跳传递，然后自然衰减。逃跑方向混合了「远离鲨鱼」和「向鲨鱼路径的侧面闪避」，后者就是喷泉效应。

鲨鱼的行为是几个转向向量的加权和：惯性、wander、追捕（瞄准猎物 0.35 s 后的位置）或巡游轨道、鲨鱼间分离、标题区的椭圆禁游区、出界回拉。选猎物时偏好前方、距离近、所在桶里鱼少的目标，所以落单的鱼先被吃。被吃的鱼在 3~8 s 后以新鱼群的形式从边缘游入，种群总数保持不变。

## 5. 锦鲤池：同一引擎的第二种用法

锦鲤池（`KOI_POND`）没有新增任何模拟机制，全部是对已有机制的重新组合，这也是检验 `Scene` 抽象是否成立的标准。

**锦鲤**就是 `SHAPES.koi`：圆钝的头、厚实的背、细尾柄、扇形的鳍、一条长背鳍。设计鳍时容易掉进一个坑：鳍的伸展距离是从脊椎量起的，而且鲨鱼式的三角鳍根部贴着脊椎，所以鳍只有超出身体半宽的那一截能露出来，而且越往外越窄。锦鲤第一版的胸鳍伸展 0.1 L，比胸部半宽（约 0.11 L）还短，结果一片鳍都看不到。现在锦鲤用 `fanFins`：三角形顶点放在脊椎上，宽边朝外，露出来的就是越往外越宽的扇面。尾鳍用 `caudalFan: 0.8`：从体长 0.8 处开始张开，末端是带浅分叉的宽扇，而不是鲨鱼那种窄叉。这里还有第二个坑：尾尖后方的所有点投影到脊椎上都落在尾尖（`u = L`），所以尾鳍的判定区域必须严格停在 `u < L` 之前；否则尾尖后面会挂上一团圆块，跟着尾巴甩来甩去。锦鲤还设了 `glossy`：用稀疏字符 `':;+=*`，墨色取皮肤本色的 62%，读起来是光滑的鳞面，不是鲨鱼的粗糙颗粒。背中线用一列 `o`，像德国鲤背上那排大镜鳞；眼睛也是 `o`，但长在头部两侧，位置分得开。鳍是白色的薄膜，根部厚、几乎不透明，往外越来越薄，到边缘透出背后的水。这个渐变只用画面已有的两个通道表达：`sampleShark` 为锦鲤的鳍算出膜的厚度（从鳍根到边缘、尾鳍从尾柄到末端，1 → 0），放进 `hitShade`；绘制时，底色通道用偏冷的白（`GLOSSY_FIN_TINT`），透出背后颜色的比例从根部的 `GLOSSY_FIN_SEE = 10%` 渐变到边缘的 65%；笔画通道按厚度从 `GLOSSY_FIN_RAMP`（边缘不画字符，根部 `:;`）取字符，并带每格的随机抖动。这样鳍的边缘会自然融进水里，在偏暖的浅池底上靠冷暖色相区分。

这里走过两个弯路。第一，沿用鲨鱼鳍的亮度、再透出 40% 的水色，鳍在任何水面上都是灰的。第二，亮色模式下白鳍和浅池底的亮度只差一成左右，我一度用 `- \ | /` 按方向画出放射的鳍条来补对比，但这引入了第三个通道（字符的形状和方向）。整幅画只有鳍在「画线」，又是按 45° 量化的整齐线条，看起来很刻意。ASCII 画面里明暗靠笔画面积，底色已经承担了颜色和大体明暗，新问题应该先在这两个通道里解决。

胸鳍从脊椎量起伸展 0.17 L，露出体外约 0.07 L；第一版取 0.22 L，看起来有半个身子宽，很不自然。花纹由 `marking()` 生成，它现在返回三种结果：无花纹、`FLAG_MARK`（深色，墨斑）、`FLAG_HI`（锦鲤红，用 `HI_TINT` 代替物种色调着色）。品种按 `sharkId` 轮换，保证一个池子里总能看到好几种：红白是在 `(s, v/L)` 上取值噪声 `valueNoise` 得到的柔和红斑；大正三色在红白的基础上叠加背部墨斑；丹顶只在头顶有一个红圆；黄金是通体橙色。花纹和字符纹理一样定义在身体坐标里，所以锦鲤游动时花纹跟着身体弯曲。

**锦鲤的游法**和鲨鱼不同，由 world.ts 里的 `MOTION.koi` 定义。鲨鱼靠速度和惯性转弯，转弯半径和体长成正比，游得慢就转得慢，所以空闲时绕着屏幕画大圈。锦鲤要「快速一拧，然后滑行」，这一点调了好几轮，每一轮都是先在 node 里量化，再找根因：

- **空闲时随机游走（`meander`）。** 下一个目标点从当前方向偏转 17°–110°、1–2.2 个体长外的 4 个候选里选，出界就夹回池内，取离其他锦鲤最远的那个。每次换方向先冲一下，再滑行减速（`burst`）；锦鲤每吃到一口饵料，也会立刻重选目标。随机偏转的权重降到 0.1，否则直线段会被掰成弧线。快撞墙时沿池壁法线推开，而不是像鲨鱼那样拉向画面中心。这几条是为了解决「锦鲤总挤在一起」：一条锦鲤约占池宽的四分之一，原来 1.5–3.5 个体长的目标点大多落在池外、被夹到池壁上，锦鲤就频繁撞墙，每次又被拉向同一个中心点，全池的锦鲤都汇集到中央。空闲时的平均间距只有 226px，撒饵后挤在一起就再也不散开。改完后平时的平均间距是 576px，接近均匀分布；撒饵后第 8 秒聚得最紧，第 20 秒恢复到平时的 94%。
- **速度由兴奋度决定，并经过两级缓动；抢食速度按身长计。** 锦鲤有一个 `excite`：瞄准饵料时约 0.3 秒升满，饵料没了以后约 3 秒回落。速度目标在空闲速度（0.75–1.5 倍巡游）和冲刺速度 `FEED_RUSH = 1.1` 身长/秒之间按兴奋度插值；离饵料 `FEED_EASE = 0.8` 个身长以内时，冲刺速度按距离降到最低 30%，滑过去吸食，不至于冲过头再绕回来。插值结果先缓动成 `pace`，实际速度再缓动去追 `pace`，所以加速度始终连续。这里走过两个弯路：一是沿用鲨鱼的「离目标越近越快」，每换一粒饵料速度就猛冲或骤停，加速度变化率峰值高达 13528 px/s³；二是把冲刺定成「巡游速度的 2.1 倍」，可这个场景为了悠闲，故意把巡游压到每秒 0.13 个身长，冲刺被一起拖慢到 85 px/s，离饵料 1 个身长的锦鲤也要 3 秒才到，30 条里有 11 条直到饵料吃光都没赶到。真实锦鲤冲刺抢食大约每秒 1.5–2 个身长。现在抢食平均 178 px/s，是空闲时的 4.5 倍；到达中位时间 1.9 秒，饵料 2–3 秒被吃光。饵料落在 `FEED_TEMPT = 4` 个身长以内，基本是整个池子，不饿的锦鲤也会过来。饵料偏离鼻尖越多，冲刺速度降得越多（最低 35%），相当于冲过头时先刹车；锦鲤靠吸食进食，吸食距离是 0.1 个身长加 8px。
- **够不着就先游开，判断必须用实际的转弯圈。** 饵料落在锦鲤转弯圈里时，硬转是转不到的，所以先直游，等饵料落到圈外再掉头。这个圈要按持续转弯时身体真正能保持的半径算：`节长 ÷ (bend × SUPPLE_CURL)`，约 0.32 个身长，再留 15% 余量。原来用的是 `turnRadius`（0.24 个身长），在 0.48–0.64 个身长这一段，规则以为够得着、放锦鲤转过去，实际又转不进去，掠过之后再判定为够不着、让它游开，锦鲤就卡在这个距离上一圈圈地绕，吃不到饵料。改完后 60 次撒饵没有一次绕圈，420 粒饵料全部吃完。
- **低速也能急转（`pivot`），但受身体弯曲余量限制（`turnRoom`）。** 脊椎是「每节跟着前一节、关节弯曲有上限」的链条。头转得比身体能弯的更快时，关节逐个卡到上限，整条弯好的身体就被当成刚体绕着头甩过去，尾巴一帧能甩出 14px：这就是「一顿一顿」。所以头部最多只能用掉前 `FLICK_JOINTS` 个关节剩余的弯曲余量；用完之后，只能边游边转，速率是「游速 × 弯曲上限 × `SUPPLE_CURL` ÷ 节长」。
- **拧身只属于转弯的开头。** 拧身额度乘以 `(1 − 前半身已弯程度)²`。否则身体回直时每帧释放出的余量会立刻被拿去继续拧，身体在整个转弯过程中都绷在上限。这一条把锁死时间从 4.8% 降到 0.6%。
- **身体有弹性（`relax`）。** 纯粹的跟随链条就像铁轨上的火车：头一拧，路径上留下一个急弯，身体要往前游完一整个身长才能伸直，锦鲤滑行慢，这个 C 形要保持 7–10 秒。真实的鱼会主动回直，尾巴扫过来对准头部方向，抄近路跟上。所以锦鲤的每个关节每秒都往直的方向释放约 3 倍的弯曲。
- **转向按偏差比例来（`SUPPLE_STEER`）。** 原来每一帧都按上限猛转，期望方向一抖，头就左右猛甩，前半身甩到一侧的上限，中段还停在另一侧，身体扭出 S 形折角。
- **几乎不互相推挤（`push = 0.25`）。** 这是没有饵料时「C 形僵硬转圈」的主因：避让力对另一条鱼的 5 个节点分别计算再叠加，两条锦鲤贴近时，避让力能达到游向目标的力的十倍，两条鱼互相推着绕圈，身体都锁成 C 形。池里的锦鲤本来就在不同深度上下交错地游，靠深度效果区分前后即可。

验收用的测量脚本是 [tools/koi-lab.ts](../tools/koi-lab.ts)（运行方式见文件头）：逐帧记录尾部节点的加速度（跳动），统计「12 个以上关节同向弯到 90% 上限」的时长（C 形锁死），并在锁死时记录目标方向、离池壁距离、最近的锦鲤。最终 5 个种子各跑 2 分钟：锁死时间 0.6%，没有一次锁死超过 1 秒，滑行段中位时长 3.4 秒。身体摆动也比鲨鱼大，波形延伸到更靠前的身体，S 形更明显（`wave: [0.065, 1.3, 6.3]`）。

**饵料**是一个 `food: true` 的物种，权重为 0，所以不会被选来生成鱼群。`seed` 时预留 48 粒饵料，状态是「死亡」，`respawnAt = Infinity`。点击时 `feed()` 激活其中 7 粒。饵料不进入空间哈希，鱼群不会把它当成邻居；它只随 `current()` 漂流。锦鲤吃饵料用的就是鲨鱼的追捕和进食代码，`onMenu()` 根据 `Scene.diet` 决定吃鱼还是吃饵料。鱼塘里 `findPrey` 取消了距离和前方锥形的限制，因为锦鲤听到食物落水会从池子另一头掉头游过来。饵料落在 2.5 个体长以内时，就算锦鲤不饿也会凑过去；抢食时锦鲤之间的避让降到三成，可以挤成一团；锦鲤的加速度是鲨鱼的两倍多，看到食物会猛冲过去。鳉鱼会被 `FOOD_SENSE` 范围内的饵料吸引过去，围着打转但不吃，锦鲤一靠近就被吓散。

**涟漪**是 `Scene.water = "ripple"` 时，把尾迹场的「模糊加衰减」换成阻尼二维波动方程（`propagate`）：

```
h' = (2h − h_prev + c² ∇²h) · damping
```

`energyTmp` 在这个模式下存的是上一步的场。这里有四个关键点，都经过数值验证：

1. **涟漪在自己的正方形网格上算（`src/ripple.ts` 的 `RippleField`）。** 字符格是 10×15 像素的长方形，竖直方向分辨率低，同一个波在两个方向上的数值色散不同；早先只靠把纵向邻居乘 `(cw/ch)²` 来校正，只校正了长波，实际看到的环横向更宽、带圆角矩形的味道。按最外侧可见波前测量，8 个方向上的半径相差 23%（横 180–189px，竖 154–160px）。现在涟漪放在 10×10 像素的正方形网格上，用各向同性的 9 点拉普拉斯 `(4·四邻 + 四角 − 20·中心) / 6`，8 个方向相差 1%；显示时按每个字符格的中心双线性采样。`c² = 1/16` 约合 155 px/s，按锦鲤 60 cm 对应约 350 px 换算，这就是雨滴涟漪的真实速度；阻尼每步 0.992。
2. **落水是振荡，不是一个鼓包。** 真实的水滴先砸出凹坑，再反弹几次，所以落水点会短暂地上下振荡，一次发出一串同心环。只放一个静止的鼓包时，第二圈只能靠二维波的拖尾（二维空间里惠更斯原理不成立）慢慢长出来，要到 0.8 秒后才出现。现在落水点按 `DROP_HZ = 4` 振荡三个周期，振幅按 `DROP_DECAY = 0.3` 秒指数衰减，第二圈在 0.4 秒内就出现，之后两三圈同时向外推。这一组参数是用 `node tools/ripple-lab.mjs` 比较几种落水模型后定的。显示阈值 `RIPPLE_SHOW = 0.08` 卡在外圈波峰和尾波之间。
3. **游动的生物不能持续往场里加能量。** 恒定的正向注入会在波动场里堆成隆起，显示出来就是满屏杂点。`stirRipples` 改成让尾巴按 `sin(phase)` 一推一拉：每摆一次尾巴发出一圈波，一个周期内的注入正负相抵。强度随速度增长，`RIPPLE_STROKE × (1 + speed / STROKE_SPEED)`。停住不动的指针也会按正弦振动，持续向外发波纹。
5. **各种扰动的大小要按「点亮多少格」来定，不能凭振幅参数猜。** 落水点要连续振荡 0.75 秒，每帧都在注入；锦鲤的尾巴每帧也在推。参数本身和最终看到的波大小差很多，必须实测。`node tools/ripple-scale.ts`（运行方式见文件头）按渲染器的驱动方式，算出每种扰动同时最多点亮多少格。现在是：一粒饵料 18 < 平时游动的锦鲤 56 ≈ 吞食 56 < 一把饵料 79 < 一滴雨 152 < 冲刺的锦鲤 199。最初的版本里，一把饵料（389）比一滴雨（202）还大，平时游动的锦鲤几乎看不见。调参时我还在测试里犯过一个错：模拟的鱼尾从画面外 130px 处出发，慢速时整段都没游进画面，一度得出「慢速尾迹怎么调都看不见」的错误结论。
6. **风（`Scene.wind`）。** 真实池塘里，风最显眼的标志不是涟漪变形，而是水面质感：无风时像镜子，起风时阵风在水面上吹出一片片细碎的波纹（「猫爪风」），顺着风向扫过去。第一版只做了涟漪随风漂移，风速 26 px/s，变形只有一两成，看不出来。现在有三层效果：
   - **阵风斑块**（`roughen`）。一张值噪声表示阵风强弱的分布，以 `GUST_SPEED` 倍于水面漂流的速度顺风移动；超过 `GUST_FLOOR` 的地方，每帧落下一些极小的随机扰动。强度按点亮格数标定：平均约 275 格。第一次凭感觉定的参数只点亮 66 格，散在全屏上根本看不出。
   - **涟漪随风漂移变形**。涟漪场每一步把两个时间层一起顺风平移（半拉格朗日、双线性取样，任何风速下都稳定）：下风一侧扩散得快，上风一侧慢，环会漂移并变成蛋形。
   - **漂浮的饵料随风漂**，速度取风速的 80%。
   
   风向由 `windAt()` 给出，在主方向附近摆动约 ±60°，风力在 40%–100% 之间起伏，变化都很慢。锦鲤池的风速是 50 px/s，约为涟漪传播速度的三分之一，对应微风下水面漂流和涟漪速度的真实比例。风可以在运行中开关（`OceanEngine.setWind`，首页右下角的按钮或 `W` 键，`?wind=off`），不会重置场景；风力按约 0.8 秒的时间常数渐强或渐弱，阵风斑块也随之出现或消退。
4. **边界：池壁或开阔海面。** `Scene.shore = true` 时边界用镜像邻居，波撞到画面边缘会反射回来，锦鲤池需要这种池壁效果。开阔海面（`shore = false`）没有墙，要把波吸收掉：画布四周铺一圈海绵层，阻尼在 `SPONGE_PX = 140` 像素内按二次方渐增，到边缘时每步 `SPONGE_MAX = 0.06`。用 `node tools/sponge-lab.mjs` 测得：以无限海面后期残留的波能为 1，镜面墙是 2.35，60px 宽、0.10 的海绵层是 1.36，140px 宽、0.06 的是 1.06。海绵层要宽而温和；阻尼越陡，自身越会引起反射。

雨滴是 `World.step` 里按泊松过程产生的 `drop` 事件，间隔取指数分布，雨点落下没有固定节拍。撒饵时，饵料撒在约 55px 范围内，在 0.25 秒内陆续落水（事件带 `delay`）；落水时被溅开的水向外推开 20–45 px/s，随后很快稳住，再随风和水流漂。在 `diet = "food"` 的场景里，吃东西不会留下红色余烬。

### 5.1 亮色模式：同一片水的白天

亮色模式不是把画面反相。反相会让明暗颠倒，鼓起的背看起来像凹槽，立体感全毁。正确做法是把亮色当成另一种水：生物是实体，光照方向和着色公式都不变，变的只是它们下面的环境。锦鲤池的 `daylight` 调色板描绘的是一个清澈的浅池，底下是浅色石头：

- **配色只换环境**：涟漪、鳉鱼、饵料都比池底深；`themed(scene, "light")` 只覆盖 `Palette` 里的字段（底色、网格、尾迹、雾、鱼、强调色、饵料、池底投影、树影），鱼群、物理参数和光照方向都不变。
- **池底投影**（`floorShadow`）是亮色版的关键特征。清澈浅池里，每条锦鲤都会在池底投下柔和的影子，这是俯拍锦鲤池最有辨识度的画面；深色水底上这些影子看不见，所以只在有 `floorShadow` 颜色的调色板里绘制。影子沿光源反方向偏移：离水面越近的鱼（`depth` 越大），影子离身体越远、颜色越淡，偏移量在 `FLOOR_DROP_DEEP` 到 `FLOOR_DROP_SHALLOW` 之间。影子用 3×3 格做软边，画在所有水中物体之下。
- **雾化强度按水质设定**（`fogStrength`）。深色水把深处的鱼吞掉，满强度雾化是对的；清澈的浅池只是轻微蒙一层，满强度会把锦鲤洗成灰白，所以亮色锦鲤池只用 35%。
- **池底反光补光**（`ambient`）。深色水里背光面就是暗的；浅色池底会把阳光反射上来，从下方照亮鱼的背光面，鱼与鱼之间的投影也被冲淡。第一版沿用了深色水的光照，背光面和投影都是炭黑色，在浅底上显得很突兀。现在未受光的皮肤按 `ambient × (1 − 0.6 × shade)` 向 `FILL_LEVEL` 抬亮，鱼在另一条鱼身上投下的影子按 `SHADOW + (1 − SHADOW) × ambient` 变淡；墨斑和眼睛是色素，保持深色，补光只照亮，不漂白。
- **半透明的鳍透出背后的颜色**。原来的写法是把亮度乘 0.6，相当于「透出黑色的水」，到了浅池里就成了深灰色的块。现在直接按 `GLOSSY_FIN_SEE` 混入场景底色，深色模式下透出暗色的水，亮色模式下透出浅色的池底，两种模式用同一条规则。

切换主题只调用 `World.restyle`，不重新生成鱼群；渲染器只在场景名变化时才清空水面，同一场景换主题，涟漪照常继续。首页默认跟随系统的 `prefers-color-scheme`，`?theme=` 优先；右下角的 `L light` 开关只在有 `daylight` 的场景显示，切换时和换场景一样淡出淡入，页面底色跟着当前水面走，避免淡出时闪一下黑。

### 5.2 树影：池边的吊钟

这里做的是树影，不是木漏れ日。树影是大部分阳光里，一角落着枝叶的剪影；木漏れ日是头顶被树冠整个遮住，大片阴影里漏下一个个圆形的光斑。两者是两种不同的阴影形态。叠在一起的话，页面会黑压压一片，盖过作为观赏主体的鱼。木漏れ日试做过一版，把光斑画成一个个圆叠加，被否掉了：圆斑简单叠加看起来像水面的波光粼粼，不像木漏れ日。真实的木漏れ日是树冠透光率和太阳圆盘的卷积：比太阳圆盘的像小的叶缝成像为圆或椭圆，大的叶缝保留自己的形状、边缘带半影，相邻的像会融成一片。后来决定不做木漏れ日，改做水下焦散和水面浮光（5.3）。它们由已有的水面波动场直接驱动，对锦鲤池的观赏性提升更大。

白天的锦鲤池上有一株吊钟（ドウダンツツジ）的影子（`canopy`，canopy.ts），右下角的 `shade` 开关（键盘 S，`?shade=off`）控制它，和 `wind` 一样会渐变，像太阳进出云层。只在主题化之后带 `canopy` 的场景显示这个开关。快捷键按物理键 `e.code` 判断，因为中文输入法下字母键的 `e.key` 是 `"Process"`。

**构图以鱼为主体。** 树从左上角的岸边伸进来，只占这一角；主干裸露的下段在屏幕外，侧枝从主干 12% 处就开始长，画面里看不到光秃秃的长枝。上边稍远处还有一根短枝单独探进来，和主树错开，所以树影是一团不对称的叶影，沿上边逐渐稀疏下去。曾经上边、左边各放过一枝，在接近正方形的屏幕上两枝沿对角线对称，看起来像是刻意从两侧包围池塘。构图要一个主体加一处偏向一侧的点缀，不要对称的两翼。池塘大部分在阳光里，锦鲤游进这一角或贴着上边游时才从叶影下穿过。影子很淡：浅池的池底同时被天光照亮，单片叶子只挡 36% 的光，枝条 50%。

**影子落在鱼身上。** 树影是在所有水中物体画完之后，作为一张图用 multiply 一次性叠到整个水面上的：池底、锦鲤、鳉鱼、涟漪一起。所以一片叶影会从石头上连续滑到锦鲤背上，再滑下去。之前的写法是把树影画在池底，锦鲤另外按采样值变暗，采样点还按水深向光源方向偏了几十像素。物理上没错，但锦鲤身上的明暗和周围的叶影对不上，看起来树影和鱼毫无关系。锦鲤只在水面下一掌深，两层之间的偏移可以忽略；而画面上的连续性就是「影子落在鱼身上」这件事本身。

**树按实物的长法生长。** 参考实物照片：主干纤细，每个节点都转折一下；侧枝一根一根互生，伸得很长，接近水平，长短错落：大约五分之一长成远远探出去的长臂，梢头挂着叶团，其余是短枝（`LONG_ARMS`）。如果只是随高度渐短，树冠外缘会连成一条直线，角上就成了一个三角形；侧枝再向两侧发出几根小枝，梢头以小角度分叉成发丝一样细的末梢；每根末梢的梢头是一轮 6 片小叶（`WHORL`，叶长约为屏幕短边的 1.6%），围着梢头均匀张开，像一把小伞，略向上兜起，所以从太阳方向看每片都短一截。每一轮叶都绕某根轴倾斜，影子被压成椭圆，所以看起来不是一个个六角雪花，而是成团的轻云。枝条的灵动来自合轴分枝：每个节点让出一根侧枝，枝条本身就朝反方向折一下（`KINK`），节间几乎是直的，转折都发生在节点上。这种折线比平滑的 S 形更像实物。梢头的分叉张成很开的 Y 形。叶形是椭圆形，最宽处在 0.4 处，基部楔形收进叶柄，叶尖渐尖（`3.47 t (1−t)(1.6−t)`）。中间有一轮试过把叶子改成 3~5 片散簇、倒卵形，被第二张实物照片否掉了：单位就是 6 片一轮，叶形也不是倒卵。每根枝都带一个整体的弯曲和一个来回的 S 形。上一版用轮生的三叉枝、梢头放射状的 5~7 叶，看起来像伞形花序，不像吊钟，而且叶子多了好几倍。

**影子沿太阳光线投下。** 高度为 z 的点，影子向背光方向偏出 `z × slant`，所以同一根茎上不同层的影子按高度在水面上错开。高度也决定影子的虚实：太阳是一个圆盘，不是点光源，离池底越高的叶子半影越宽，天光散射进来的补光也越多，影子越淡（`HIGH_FADE`）。虚实不按每单位高度的半影绝对值算，而是按树冠内部的相对高度：最低的叶子最清晰，最高的叶子达到 `softest` 级，中间按高度线性过渡，相当于把景深夸张了。用绝对半影值时出过两次问题，一次所有枝都挤在前 40% 的虚实区间里，看起来一样黑；一次把系数调大，整棵树都糊了。原因是绝对值同时受屏幕尺寸和树形影响，一动就整体偏移。按相对高度算，前后层次总能拉开。三根茎的根部高度也不同（`foot`）：主茎长在高岸上，整个树冠都高，所以虚而淡，在后面；左下那根贴着水长，所以清晰而深，在前面。`base` 定义为根部影子落下的位置，所以调根高不会改变构图。渲染上，每个部件按高度直接光栅化进 4 级光照缓冲之一，每级分辨率是上一级的一半；在粗的那级里光栅化，本身就已经是模糊，再逐级 2× 放大乘进更清晰的一级，就继续变软。介于两级之间的部件按比例分到两级，所以虚实随高度连续变化。这是 Leaves.ts 里模糊金字塔的同一个思路，只是把「先画清晰再模糊」换成了「直接画进对应的那一级」。

**叶子是半透明的。** 每片叶子把它覆盖的光乘以 1 − α，所以重叠的地方影子更深。小于一个采样点的部件按面积做双线性 splat，摆动时在缓冲里连续滑动，不会一格一格地跳。树影画在石头上，不在字符网格上，所以它是一张连续的图，用 multiply 叠到池底，再在上面画鱼。锦鲤在池底的投影要乘池底透过率，因为已经在树荫里的地方没有阳光可挡。

**风。** 每根枝摆动的幅度取自让水面起猫爪纹的同一个阵风场（`gust()`）。阵风场的漂移量必须按 `wind × dt` 逐帧积分。原来的写法是 `wind × t`：风渐强或渐弱的那几秒里，漂移量以 Δwind × t 的速度扫过整个噪声场，而 t 早已是几百秒，于是开关 wind 时树影剧烈抖了大约三秒。水面的猫爪纹也有同样的毛病，只是没那么显眼。

**走过的弯路。** 第一版照搬 Leaves.ts：二维侧视图当作一面屏风，按格子量化。结果有四个问题：颗粒粗，叶子不通透，没有高低差，摇起来一顿一顿。四个都出在表达层：影子按格子量化，移动时一次跳 12 px；不透明的叶子叠在一起不会更深；平面屏风里所有部件的半影和偏移都一样。第二版用 Path2D 画进多级 canvas，每帧约 17,000 次路径调用，每次约 1 µs，而树本身的全部计算不到 1 ms；改为在 Float32 缓冲里直接光栅化。叶子轮廓函数里的 `pow` 和 `sin` 每帧要算二十万次，一项就占了 15 ms，换成多项式和 `sqrt` 以后就降了下来。第三版按实物照片重做了枝叶形态，又把整体减淡、退到画面一角。叶子缩小一半、轮数加倍以后，每帧又涨到约 5 ms，又做了两处优化：细枝 splat 从每个采样点两次降到一次；每级缓冲只记录本帧碰过的包围盒，清空、逐级放大和写图像都只在框内做，树影只占画面一角，其余部分全是阳光，什么也不用做。在 node 里单测 update 约 2.3 ms，headless Chrome 会更慢一些。顺带一条教训：Chromium 的 profile 会把内联进来的函数算在调用方头上，所以看到 `walk` 很贵，起初以为是三角函数的开销；在 node 里关掉内联、按行看 tick，才发现真正的开销在光栅化。

树按屏幕短边定尺寸，从左上角往外长，所以横屏和竖屏用同一个构图，竖屏时树影落在上半屏。窄屏下开关栏移到场景栏上面一行。

### 5.3 水下焦散与水面浮光

白天的锦鲤池有焦散和浮光（`caustics`，caustics.ts）。两者都直接取自涟漪场已经模拟出来的水面，所以雨滴、锦鲤摆尾、阵风在水面上激起的波纹，会同时在池底激起一张光网，在水面上闪出几点浮光。

**焦散按光线计算。** 每 5 px 放一条阳光，按它所在处的水面坡度折射偏移，落到池底时双线性分摊到四个采样点上。波谷像透镜一样把邻近的光线汇聚起来，那里分到的光多于平均份额，形成亮线，亮线交织成网。静水会把光均匀铺开，什么也看不出来，所以光网只在有波纹时存在。光网的网眼和造成它的波一样宽：直接用风吹出的细碎粗糙面，光网会又密又碎，所以先把坡度场平滑三遍，只让较大的起伏来折光，聚焦距离（`focus`）也相应加大。光线要经过一段深度才会聚焦，所以光网落在池底，在鱼的下面。

**风浪：泳池式的光网。** 只靠涟漪场时，光网只出现在雨滴、鱼尾、阵风扰动过的地方，看起来是一圈圈涟漪。夏日泳池那种铺满池底、细线交织成不规则多边形、缓慢漂移变形的光网，来自风浪：许多波长相近的小波从风向两侧同时交叉。所以在涟漪的坡度上再叠一层风浪（`swell`）：12 道波，波长 120–340 px，强度各不相同（8 道等强的波会排出一张过于规整的准周期网），方向在主风向两侧 ±70° 展开，波速按深水波的规律随波长的平方根增长，所以光网会一边漂移一边变形，而不是整片平移。风浪只参与折光，不出现在涟漪点里。它的强度跟着让水面起猫爪纹的那个阵风场走：阵风扫过的地方光网才出现，平静的地方池底留白。这样光网和雨滴、锦鲤的尾流一起，只出现在水被扰动的地方，而不是均匀铺满（均匀铺满时「分布太平均」）。风停时保留一点。计算时在涟漪网格的节点上求值，把正弦拆成列表乘以行表，每道波每个节点只要两次乘法。

**浮光按镜面反射计算。** 从正上方看，只有朝太阳倾斜到足够陡、正好把阳光反射到观察者眼里的水面才会闪光。实测这片水面朝向太阳的坡度，99% 低于 0.005，99.9% 低于 0.008，所以阈值取 0.006–0.012：只有最陡的千分之几会闪光，看起来是一个个火花，而不是一层光泽。浮光用的是未平滑的坡度，因为镜面反射是锐利的。一个陡坡面会同时点亮一小片采样点，所以按亮度从高到低挑，3 格以内只留一个，否则会结成一团。

**用 ASCII 来画。** 第一版把光画成连续的图像：暖白的亮线、灰色的暗区、四芒星的浮光。物理上是对的，但和字符画的锦鲤放在一起，风格割裂。现在光和池里其他东西一样，按格子用字符和颜色来画：每格取落进来的最亮的光，用最大值而不是平均值，所以几像素宽的细线也能读成一行字符。用白色字符，保留原来那种白色光圈和光网的样子。光网用不带方向的「光珠」来画：`. : o`，亮度越高字符越饱满、墨色越重，墨色分 8 档。每格取落进来的光的平均值和最大值各一半：只取最大值，细线在宽格子里也会被画满；只取平均值，每条线都会被格子切成方块。这样宽而柔的光线会自然占几格并在边缘变淡，细线保持细，每条线的粗细由光本身决定。线宽也试过用规则来控制：横穿线的方向做非极大值抑制、两侧补淡点作晕边，结果每条边都是一两个字符，粗细变化显得很假。光强是长尾分布，满阵风下，十分之一的格子高于 0.9，二十分之一高于 1.6，百分之一高于 4.2，所以显示最亮的约六分之一，并按对数映射。试过顺着线的走向放 `- \ | /`、交汇处放 `+`，结果「全是规整的线，太奇怪了」。这和锦鲤鳍上的教训一样：方向字符会把形状硬压进四个方向，哪怕画的东西本身确实是线。只画亮的一侧，不画暗区，池底保持干净。浮光是一个单独的 `*`，画在水面上，盖在所有东西之上，3 格以内只留一个。它要和三样东西分开：白色的光网、深色的涟漪点、棕色的饵料。只靠颜色分不开，金色的 `*` 和棕色的饵料都是暖色的小点，曾经被认混过。所以用物理上的区别来分：饵料是一直不动的颗粒，浮光随着波纹经过一闪一闪。饵料也从小圆点 `•` 换成了实心大圆点 `●`，读起来是水里的一个东西，而不是一点光。浮光的字符随强度变化，渐起和渐落时是 `+`，最亮时是 `*`，所以会闪烁；颜色用日光的黄色。试过在后面加一圈柔和的白色光晕，但「加光晕不是 ASCII 视觉体系的」：区分必须用字符本身（字形、颜色、随时间的变化）来做，不能用渐变之类绘画手段。在树荫里两者都会随着直射阳光一起减弱。

**树影不换成字符。** 树影也试过同样的换法：用每格的平均暗度和最暗值的混合，按实测分布分档（暗格里一半低于 0.13，四分之一高于 0.2，十分之一高于 0.26），依次映射成 `: + % #`。结果整体风格统一了，但看不出是吊钟了。吊钟的辨识度在叶形和枝条走向上，这些都比一格还细，换成字符以后只剩一片斑驳。所以树影仍然是连续的图像，用 multiply 叠在水中所有东西之上。焦散和浮光的辨识度在线条和光点上，换成字符以后还在。判断能不能换成字符，就看一个效果靠什么被认出来，以及这个特征比一格大还是小。

## 6. 座头鲸气泡网：一个会讲故事的场景

`WHALES` 场景要讲一个循环：磷虾聚成一团，几头鲸围着它绕圈、吐出一圈气泡帘，把磷虾往中间赶，然后张嘴从中心冲上来吞食，浮出水面激起大浪，散开休息，磷虾从边缘重新游进来。鲨鱼的追捕是各自为战，这里是协同捕食，所以 `Scene.hunt = "bubble-net"` 时，`stepSharks` 改走另一条转向分支。其余部分照旧，包括动量、wander、出界回拉、脊椎跟随和侧倾。

**鲸群的时钟**是 world.ts 里的 `Pod`，只有三个阶段：

1. `rest`：鲸鱼按普通巡游路线游，磷虾聚集。时间到后，`densestSwarm()` 从空间哈希里选一团磷虾：评分是密度乘以 `exp(−距离 / 0.8 短边)`，偏好离鲸群近的，不会满屏跑去追最远的那一团。
2. `net`：离圆圈太远的鲸先直接游向圆圈，到了之后切向绕圈，同时有径向力把它拉回圈上。每游过 `BUBBLE_SPACING` 就在头部下方吐一个气泡。圈的半径在 `NET_TIME` 内收缩到 `NET_CLOSE`，圆心缓慢追随圈内磷虾的质心。领头鲸绕满 `NET_TURNS` 圈后进入冲刺。
3. `lunge`：每头鲸冲向「圆心偏向自己那一侧」的点，所以会并排浮起，不会叠成一团。张嘴程度 `gape` 渐升到 1，`gulp()` 静默吞掉嘴里的磷虾，不逐只发事件，否则几十个涟漪会同时炸开。`LUNGE_TIME` 结束时，每头鲸的头部发一个 `splash`，在涟漪水面上就是一圈大浪。

**气泡**是 `World.bubbles`：上浮 `BUBBLE_RISE` 秒，浮出水面时有一半概率发出强度 0.3 的 `drop`，形成细小的嘶嘶涟漪；之后从圆心向外漂开，`BUBBLE_LIFE` 秒后消失。在上浮阶段和浮出后的 1.5 秒内，气泡会把 `BUBBLE_R` 范围内的鱼推开，这就是气泡帘。气泡帘把圈外的磷虾往外推、圈内的往里推，再加上鲸鱼本身从圈外施加的恐惧，磷虾就被赶向圆心。磷虾的 `fear = 0.2`，只会勉强躲一躲，否则鲸鱼一靠近，整群磷虾就散出圈外了。

调这个场景踩过三个坑，都是用 node 单独跑模拟层、记录各阶段时间点查出来的：

- **网要跟着鲸鱼一起变大，而不是反过来缩小鲸鱼。** 网的半径有一个下限：鲸身最多只能弯到约 L/3 的半径，网再小，鲸鱼就贴不住圈，实测网半径要在约 0.55 L 以上。第一版网收缩到 0.42 L，鲸鱼兜不住圈，只能在圈内外来回冲。第二版为了满足约束把鲸鱼缩小到 180–210px，代价是鲸鱼看起来像小杂鱼，丢掉了这个场景要讲的尺度反差。现在是一头成年鲸（约 350px）带两头小鲸（约 0.6 倍体长，游在更深处，雾化后偏蓝偏暗），大小和深度一起拉开层次。网半径从短边的 36% 收缩到 26%，相当于成年鲸体长的 0.82 倍到 0.59 倍，直径接近 600px，几乎铺满屏幕。
- **鲸群工作时不互相避让。** 鲨鱼之间的避让范围是体长和的 0.45 倍，对鲸鱼来说接近 200px，会把彼此推离圆圈。真实的鲸群是一头跟着一头在同一个圈上游。
- **圆心要跟着磷虾走。** 磷虾随洋流漂移，圆心固定不动的话，十几秒后网里就空了。

**座头鲸体型**：扁平宽阔的头部散布着瘤状突起（`marking()` 返回 `FLAG_RIDGE`，画成亮色疙瘩），背后靠后的位置有一个小背鳍突起，尾叶是宽扇形（`caudalFan`），没有腹鳍。胸鳍（`flipper`）不是三角形，是一把宽度几乎不变的长刀：由 `inFlipper()` 沿「肩部 → 鳍尖」的轴线判定，宽度向外略微收窄，末端 15% 收成圆头。上表面是深色皮肤；只有前缘（朝头的那一侧，宽度占 60%–100% 的那一段）是一道浅色边，按 `pectoralTint` 着色，每隔一段画一颗瘤状突起（`FLAG_RIDGE`）。第一版先后犯了两个错：先是三角形根部太窄，伸出身体的那段只剩一条灰色细线；改宽之后又把整片胸鳍涂成全身最亮的白色。对照照片，座头鲸胸鳍从上方看主要是深色的，白色只在前缘和下表面。张嘴时 `gape` 让头部后方的喉囊鼓起，最多加宽 80%，并露出浅色的喉褶条纹。

还有一个通用的坑：`pelvic` 全设为 0 表示没有腹鳍，但三个顶点重合的退化三角形在 `inTriangle` 里会包含所有点。所以腹鳍判定要先检查 `vr > 0`。

## 7. 改造指南

### 不变量

| 不变量 | 守护者 | 破坏后果 |
|---|---|---|
| 关节偏转 ≤ `maxBend` | `stepSharks` | 身体对折、自穿 |
| 形状参数是体长分数 | `SHAPES` | 尺寸变化时形状失真 |
| 字符选择锚定在 `(s, v)` | `rasterizeSharks` 的 `key` | 纹理在皮肤上滑动 |
| `SKIN_RAMP` 从稀到密，对应从亮到暗 | `drawSharks` | 立体感消失 |
| 鱼的间距以格子为单位 | `World.resize` | 鱼重叠在同一格、丢失 |
| 行波只在渲染层 | `rasterizeSharks` | 捕食判定随摆尾抖动 |
| 横滚只移动标记，不改光照 | `sampleShark` 的 `fromBack` | 光源看起来随鲨鱼旋转 |
| 亮色模式只换环境，不反相、不改光照 | `Scene.daylight`、`themed` | 明暗颠倒，立体感变成凹陷 |
| 鳍的俯视长度 ≤ 真实长度，一律经 `cos` 投影 | `rasterizeSharks` 的 `finTip*` | 转弯时外侧鳍被拉长，违背透视 |
| 场景只存在 `World.scene` 一处，渲染器只做派生 | `AsciiRenderer.render` 里的引用比较 | 切换后配色和生物不同步 |
| 鳍的伸展距离（从脊椎量）必须明显大于鳍根处的 `halfWidth` | `SHAPES` 的 `pectoral[3]`、`pelvic[3]` | 鳍藏在身体里看不见，或者只剩一根尖刺 |
| 尾鳍判定区域严格停在 `u < L` 之前 | `inCaudal` | 尾尖后面挂一团圆块 |
| 胸鳍、腹鳍在鳍根处的直框架里判定，不用随身体弯曲的身体坐标；姿态只能靠绕鳍根旋转来摆，不能拉伸 | `pecFrame`、`pelFrame`、`spineFrame`、`poseFin` | 转弯时外侧的鳍被抹成一条长条，内侧的被压成细棍 |
| 鳍根不往后掠过静止姿态 | `finSweep` | 鳍埋进身体，看起来像在缩短 |
| 生物按深度从深到浅光栅化；近处的轮廓边缘不覆盖更深生物的实心格 | `seed` 的排序、`rasterizeSharks` | 交叠处被打出洞，两条生物糊成一团 |
| 明暗只用两个通道：底色（色相与大体明暗）和笔画面积（浓淡）；不用字符的形状、方向去画结构 | `drawSharks` | 局部出现规整的线条，和整幅画的语言不一致，显得刻意 |
| 阴影只压暗比投影者更深的生物 | `sharkShadow` 存投影者深度 | 生物被自己的影子压暗 |
| 最小转弯半径 ≥ 身体能弯到的半径 `L / (19 · bend)` | `MOTION` 的 `turnRadius` 与 `bend` | 急转时身体折成 L 形 |
| 头部转向不超过身体剩余的弯曲余量；拧身额度随前半身弯曲递减 | `turnRoom` | 弯好的身体被刚性甩动（一顿一顿），或整个转弯过程都锁成 C 形 |
| 柔软的鱼要有回直力，不能纯跟随路径 | `MOTION.relax` | 一次拧身留下的 C 形要保持一整个身长的游程 |
| 随机游走的生物撞墙时沿法线推开，目标点不超出池子太多 | `stepSharks` 的出界回拉、`meander` | 全池汇集到画面中心，撒饵后一直不散开 |
| 锦鲤的速度只经由两级缓动变化，不直接跟随离目标的距离 | `excite` → `pace` → `speed` | 每换一粒饵料就猛冲或骤停 |
| 「够不着先游开」用持续转弯的实际半径判断 | `stepSharks` 追捕分支里的 `circle` | 锦鲤绕着饵料一直转，吃不到 |
| 涟漪水面只接受正负相抵的注入 | `stirRipples` | 波动场堆出隆起，满屏杂点 |
| 只有大型生物搅动涟漪水面，小鱼不搅 | `stirRipples` | 几百只磷虾把水面搅成满屏杂点 |
| 气泡网半径 ≥ 约 0.55 个鲸体长；鲸鱼变大时网跟着变大 | `WHALES.sharks` 的 size、`pod.radius0`、`NET_CLOSE` | 鲸鱼兜不住圈，来回冲；或者鲸鱼缩成小杂鱼 |
| 开阔水面的涟漪边界吸收，不反射 | `Scene.shore`、`buildSponge` | 波在画布四周来回回荡，像在泳池里 |
| 没有的鳍伸展设为 0，并在判定前检查 | `sampleShark` 的 `vr > 0` | 退化三角形把整个包围盒都涂成鳍 |
| 涟漪在正方形网格上用 9 点拉普拉斯计算；波速满足 `c² < 0.75` | `src/ripple.ts` | 环变成圆角矩形；超过上限则数值爆炸、整屏闪烁 |

### 已知局限

这套立体感只在单一视角下成立。它是正交俯视的 2.5D：横截面永远假定为圆柱，没有真正的高度场，鲨鱼不能翻滚或俯冲。

横滚目前只移动了背鳍和腹部。眼睛和鳃裂仍按 `across > 0.6` 判断，所以不会跟着横滚移动；高耸的第一背鳍在横滚时，鳍尖应该比鳍基偏得更远，目前也只按鳍基平移。如果要继续，把这些判断改用带符号的 `across × sign − rollX` 即可，眼睛在内侧会被身体遮住，在外侧会抬起来。腹部提亮受光照约束：背光一侧的腹部本身就暗，所以向左转时腹部不如向右转时明显，这是光源方向带来的，不是 bug。

性能上，`sampleShark` 对每个样本遍历全部 19 段脊椎，每格 5 个样本，乘以包围盒内的格子数，这是主要开销。如果要增加鲨鱼数量或节点数，先考虑按包围盒裁剪脊椎段，或者利用相邻格子的最近段相同这一点做局部搜索。
